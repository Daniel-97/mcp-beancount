# M2 — Tool `query` (BQL in sola lettura) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Eseguire query BQL di sola lettura sul ledger corrente, con colonne, righe serializzate, limit/offset, `truncated` e `total_rows`.

**Architecture:** `queries.py` valida lo statement, esegue con beanquery e pagina il cursore; `tools/query.py` formatta la risposta ei errori; `server.py` registra il tool. I test completi verranno scritti nella fase finale, come richiesto.

**Tech Stack:** Python >= 3.11, beanquery 0.2.0, Beancount 3.2.3, MCP SDK 2.3.0.

**Spec:** `spec.md` §6.2, §7, §9, §11 M2

## Global Constraints

- Solo statement di lettura tabellari: `SELECT`, `BALANCES`, `JOURNAL`. `PRINT`, DDL e qualsiasi altro statement sono rifiutati con `QUERY_ERROR`.
- `limit` default = `Config.query_limit` (default 100), massimo 1000; `offset` >= 0. Violazioni → `LIMIT_EXCEEDED`.
- Le risposte hanno sempre `ok: bool`; gli errori usano `{ok: false, error: {code, message, details, hint}}`.
- Gli importi/quantità sono stringhe, mai float JSON.
- Il ledger viene caricato da disco a ogni chiamata tramite `LedgerService.load()`.
- I test automatici di M2 sono stati aggiunti nella fase finale (suite completa: 271 test).

## Review Focus

- BQL con sintassi errata o statement non tabellare: risposta `QUERY_ERROR` strutturata, nessuna eccezione MCP.
- `limit`/`offset` oltre i bordi: `LIMIT_EXCEEDED`, nessuna query eseguita.
- `total_rows` e `truncated` devono essere corretti con e senza `LIMIT` nel BQL.
- Valori `Amount`, `Position`, `Inventory`, `Decimal`, date e set devono essere JSON-serializzabili e leggibili.
- Ledger mancante o illeggibile: `LEDGER_ERROR` strutturato, come `ledger_info`.

### Task 1: `queries.py`

**Files:**
- Create: `src/beancount_mcp/queries.py`

**Interfaces:**
- Consumes: `LedgerService`, `LedgerSnapshot`, `ErrorInfo`, `error_response`, `Config`.
- Produces:
  - `run_bql(service: LedgerService, bql: str, limit: int | None = None, offset: int = 0) -> dict[str, Any]`

**Comportamento:**

1. `effective_limit = service.config.query_limit if limit is None else limit`.
2. Se `effective_limit < 1 or > 1000`: `LIMIT_EXCEEDED`.
3. Se `offset < 0`: `LIMIT_EXCEEDED`.
4. Caricare lo snapshot con `service.load()`; `LedgerError`/`OSError` → `LEDGER_ERROR`.
5. `conn = beanquery.connect("beancount:", entries=list(snapshot.entries), errors=[], options=snapshot.options)`.
6. `stmt = conn.parse(bql)`; `ParseError` → `QUERY_ERROR`.
7. Consentire solo `beanquery.parser.ast.Select`, `Balances`, `Journal`; altrimenti `QUERY_ERROR` con hint.
8. `cursor = conn.execute(bql)`; catturare `rowcount` prima di leggere; `description` per le colonne.
9. Saltare `offset` righe con `fetchmany`, poi leggere `limit + 1` righe.
10. `truncated = len(rows) > effective_limit`; tagliare a `effective_limit`.
11. Serializzare ogni valore con `_serialize`.
12. Risposta:

```python
{
    "ok": True,
    "columns": [{"name": str, "type": str}],
    "rows": list[list[Any]],
    "limit": int,
    "offset": int,
    "truncated": bool,
    "total_rows": int | None,
}
```

**Serializzazione:**

- `Decimal` → stringa con `format(value, "f")`.
- `Amount`/`Position`/`Inventory` → `str(value)`.
- `date`/`datetime` → ISO.
- `set`/`frozenset` → lista ordinata di valori serializzati.
- `list`/`tuple` → lista ricorsiva.
- `dict` → dict ricorsivo.
- `bool`/`int`/`str`/`None` → invariati.
- `float` → stringa.

**Tipo colonna:** mappa `str`→`string`, `int`→`integer`, `Decimal`→`decimal`, `date`→`date`, `datetime`→`datetime`, `bool`→`boolean`, altrimenti `__name__`.
